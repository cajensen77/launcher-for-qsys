Launcher for Q-SYS

An address book and launcher for Q-SYS Designer: your Cores, the right Designer version, hard links that keep themselves up to date, and a live list of the Q-SYS devices on your AV network.

Getting started

  1. Keep QSysLauncher.ps1, Start QSys Launcher.cmd, QSysLauncher.ico and this help file together in one folder (for example Documents\QSysLauncher).
  2. Double-click Start QSys Launcher.cmd. It uses the PowerShell that comes with Windows — nothing to install.
  3. The first time, it imports the hard links you already have in Designer and starts checking every Core. If you have none yet, a welcome panel shows how to add Cores — the easiest way is the Devices tab, where Cores on your AV network appear by themselves.
  4. To read firmware from Cores that have Access Control turned on, set a Core login once: Tools > Core login...
  5. Optional: Tools > Options > Start with Windows so it's always running in the tray, and File > Create desktop shortcut for a shortcut with the app's icon.
  6. The first time it listens for devices, Windows may ask whether PowerShell may use the network. Allow it on Private networks so the Devices tab can hear announcements.
The window title and the bottom-right corner show the version that's running (for example v0.22). The app has its own taskbar button and icon; right-click it > Pin to taskbar to keep it there. Starting the launcher again from the .cmd replaces an older copy that's still running, so after an update you always get the new version.

What happens automatically

The launcher listens; it doesn't knock. Talking to a Core over the network (Remote Control on port 1710, or Core Manager for firmware) adds client connected / closed lines, and sometimes a sign-in, to that Core's event log. So by default it only talks to a Core when you ask. Every 5 minutes, with no buttons to press:

  1. New Designer versions are picked up from C:\Program Files\QSC.
  2. Hard links added inside Designer are imported into your list.
  3. Cores are followed from their announcements on LAN A (QDP), which leave no trace on the Core: Heard on LAN A or Not heard, name, LAN A and LAN B addresses. A new LAN B address updates the row and the hard links right away. New Cores are added (see Adding Cores automatically).
  4. Designer's hard links are rewritten if anything changed. If Designer is open, this waits until Designer closes.

When the launcher talks to Cores (and so shows in their logs):

  • Check all now (F5): every Core on port 1710 (design, state, model). Firmware is read from Core Manager only where something could have changed (see Firmware).
  • Check now on selected rows (right-click): those Cores, including firmware.
  • Launching a Core whose firmware isn't known yet, or that went quiet since its last check (a firmware update means a reboot): that one Core is checked first, then Designer opens.
  • Options > Check Cores over the network: set it to every 30 min, 60 min or 4 hours if you want automatic checks anyway. The default is Only when I ask.

The main window

  • Search filters by name, group, either IP, design, model or notes.
  • Launch Designer opens the Designer version that matches the selected Core's firmware. Double-clicking a grey column does the same.
  • + / − under the list add a Core (type a name and its LAN B IP; everything else fills in on the next check) or remove the selected ones.
  • Check all now (F5) checks every Core over the network (see What happens automatically).
  • Right-click a row for: Launch, Open Core Manager, Check now (incl. firmware), Trust this Core's new certificate, Remove.
  • Installed Q-SYS Designer (right side): every version on this PC. Double-click or Launch this version to open it without a Core.
  • The status bar at the bottom shows the last check; the full detail is in View > Log.
  • Columns size themselves to fit their contents. Drag a column edge to resize it, or double-click the edge to re-fit.
  • The main window and the Log window remember their size and position (and whether they were maximized). If that spot is no longer on any monitor, they open centered instead.

Devices tab (live discovery)

Every Q-SYS Core and peripheral announces itself about once a second (Q-SYS Discovery Protocol, QDP). The Devices (LAN A) tab listens for those announcements and builds a live list — nothing to type in.

  • It listens only on the network card that's on your LAN A (AV) network, so Q-SYS gear on other networks (e.g. another department's, on a shared building network) isn't shown.
  • You don't have to tell it which network that is: until it knows, it listens on every network, and the first Core it checks (or the first device it hears) tells it the LAN A range. You can override it in Options.
  • Name is the device's network name as it announces it — devices report these in lowercase. Cores that are in your list show their proper name instead.
  • Kind (Core, Touch screen, Amplifier, Video endpoint, Camera, I/O, Speaker, Paging station...) is worked out from the model number, because the type a device announces is coarse (most peripherals just say "ioframe"). Hover to see the raw type.
  • Status: Live = heard in the last 15 seconds; Not live = it stopped announcing (off, unplugged, or rebooting). Hover Not live to see when it was last heard.
  • In Cores list as: for a Core, the name of its row on the Cores tab. Blank = that Core isn't in your list yet (see Adding Cores automatically).
  • Right-click: Open web page · Copy IP address · Add this Core to my Cores · Add all Cores not in my list · Forget devices not heard now.
  • Cores in your list are kept current from their announcements: the Core's own name is filled in, and if a Core announces a new LAN B address, the row and Designer's hard links update immediately.
  • Cameras: NC Series cameras announce themselves and appear automatically. The older PTZ-IP cameras use a different method (WS-Discovery); turn on Options > Also find PTZ-IP cameras to include them. The launcher then asks the AV network while the Devices tab is open (at most every 5 minutes) and shows only cameras that identify as QSC / Q-SYS (other brands are skipped, and noted once in the log).

Adding Cores automatically

Each Core's announcement already carries its name, LAN A address and LAN B address, so with Options > Automatically add Cores heard on LAN A to my Cores list on (the default), Cores you haven't entered are added by themselves — and, with auto-sync on, go straight into Designer's hard links. Even if your PC talks to the Cores on LAN B, it can hear them on LAN A.

  • Only your AV network: a Core is added only if its LAN A address is inside your LAN A range. Until that range is known, nothing is added.
  • Not emulators: Cores that announce themselves as virtual or emulated are never added.
  • Removed means removed: removing a Core puts it on a removed list, so it isn't added back. On a shared list the whole team shares the removed list. To bring one back, right-click it on the Devices tab > Add this Core, or press Allow them again in Options to clear the list.
  • Few logins: filling in the row needs no login. Firmware isn't in the announcement, so each newly added Core gets one Core Manager read; after that the usual rules apply (a login only when a new design is pushed or the Core was down).
  • New Cores are collected and checked together, with one tray note listing them. Rows are named from the announcement, then given the Core's proper upper/lower case when the check comes back. Rename them freely.
  • Nothing is added in the first 2 minutes after the launcher starts, so the startup check can recognize Cores you already have.
  • Add all Cores not in my list (right-click on the Devices tab) does the same in one go, for when the option is off. The log says which Cores it skipped and why.

Tray icon

  • Left-click opens the window. Right-click: your Cores (click one to launch its Designer), Designer versions, Log, Options, Check all Cores now, Exit.
  • The window's X keeps the launcher running in the tray (change this in Options). Minimize keeps it on the taskbar like any program.
Don't see the icon? Windows puts new tray icons in the hidden area. Click the ^ arrow next to the clock — it's there. Drag it onto the taskbar to keep it visible, or turn it on under Windows Settings > Personalization > Taskbar > "Select which icons appear on the taskbar". You can also just run the .cmd again: it brings the running launcher back up.

Launching Designer

Launch for a Core (button, double-click, right-click, or the tray menu) opens the Designer version matching that Core's firmware. Then, depending on Options > After Designer opens:

SettingWhat happens
OffJust opens Designer.
Open dialogOpens File > Load from Core & Connect once Designer is ready.
Select Core...and selects this Core's row in the list, found by its Core name (e.g. SantaSusana-Core). Nothing is typed, so Designer's search box is left alone. You click Load. If the row can't be selected directly, it types the Core name into the search box instead.
Select + Load...and clicks Load From Selected Core too (only when there's exactly one match).

Timing: a tray note appears as soon as you launch, and the status bar shows what Designer is doing (loading screen, busy...). F8 is pressed about a second after Designer is ready to use. Designer has no remote-control interface, so the launcher operates it through Windows' accessibility interface (UI Automation): it opens the menu item, selects the row and clicks Load directly — no mouse or keystrokes, and Designer doesn't need to be the window in front, so you can keep working elsewhere. One exception: Designer's menus close when its window isn't the active one, so if you're working in another window, the launcher brings Designer forward for a moment to open the menu item, then hands focus back to your window as soon as the dialog is up. Only if the menu can't be found at all does it press F8 instead.

The Core name is also put on the clipboard, so Ctrl+V in the search box always works. If the F8 automation can't find the dialog, it saves designer-ui-dump.txt in the data folder for diagnosis.

Hard links (LAN A / LAN B)

Every installed Designer version reads the same two files: %AppData%\QSC\HardLink.json (addresses) and HardLinkNames.json (names, Designer 10.5+). The launcher keeps its own richer list and writes just the addresses and names into those files.

  • Options > Core address to use: LAN B (campus), LAN A (AV network), or Both (the LAN A link is named "Name [A]" in Designer). A row that only has one address always uses the one it has.
  • The launcher's list is in charge. Remove Cores in the launcher (Edit > Remove). If you delete a hard link inside Designer, the launcher puts it back on the next check.
  • Links you add inside Designer are imported automatically.
  • Every write keeps a backup of Designer's files in backups in the data folder (newest 20 kept).

When a Core's address changes

LAN B addresses without DHCP reservations can change when a lease renews. Every Core announces its current LAN A and LAN B addresses on LAN A about once a second, so while the launcher is listening there, a new LAN B address updates the row and Designer's hard links within seconds, with a tray note. Nothing is scanned.

Without a network card on LAN A, the launcher can't hear that. The Core shows No response on the next check: type its new address in the row (or remove it and add it again).

Network and security notes

  • Listening on LAN A only receives the announcements the Cores send anyway.
  • Which network card: only the one on LAN A. If the LAN A range isn't known yet, the launcher first looks for a card on the same network as a LAN A address in your list. Failing that, it listens on every card for up to 5 minutes to hear a first Core, then stops. A PC with only a LAN A card, only a LAN B card, or both, all work. When cables or networks change (a laptop moving between rooms), it picks the card again within 15 seconds.
  • No scanning: the launcher never sweeps address ranges. It only contacts Cores in your list, when you ask.
  • HTTPS certificates: Cores use self-signed certificates. The launcher remembers each Core's certificate the first time it connects ("trust on first use", as SSH does) and afterwards only accepts that same one, so your Core login is never sent to something pretending to be the Core. If a Core is reset, replaced or re-imaged and gets a new certificate, the log and a tray note say so: right-click it > Trust this Core's new certificate.
  • PTZ-IP cameras (if turned on): the camera question goes out only while the Devices tab is open, at most every 5 minutes.

Firmware and Core login

Firmware comes from Core Manager (/api/v0/cores/self). Cores with Access Control need a login: Tools > Core login... sets one login used for all Cores. If some Cores use a different login, right-click those Cores > Core login for this Core... — you only maintain the exceptions. The password is stored encrypted for your Windows account only (Windows DPAPI) — never as plain text.

To keep your Cores' event logs clean, the launcher only logs in when firmware could have changed:

  • it doesn't know the Core's firmware yet,
  • the Core's design code changed (a design was pushed — which always follows a firmware update), or
  • the Core just came back after not answering (it may have rebooted).

Otherwise checks use port 1710 only, which needs no login. To force a fresh read, use Edit > Check selected now (incl. firmware).

Sharing one list with a team

If two or three people look after the same system, point everyone's launcher at the same folder: Tools > Options > Shared Core list folder (a OneDrive/SharePoint folder or a network share).

  • The Core list lives in LauncherForQSYS-cores.json in that folder. Each PC also keeps its own copy, so the list is still there if the share is offline.
  • Changes are merged row by row: a Core someone adds appears for everyone, a Core someone removes disappears for everyone, and if two people edit the same Core, the most recent edit wins.
  • Not shared: logins (passwords are encrypted for one Windows account and can't be moved), Options, and window positions. Each person sets their own Core login once.
  • Turning sharing on with a list already in the folder merges the two — nothing is lost. Clearing the folder keeps everything on your PC.
